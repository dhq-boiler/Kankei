# Kankei（還景）引き継ぎ資料

更新日: 2026-09-11

## 1. プロダクト概要

**Kankei（還景）** は、Windows を終了・再起動した後に、以前の作業環境を可能な限り元の状態へ戻すローカル常駐アプリです。

> 作業の景色を、いつでも還す。

保存・復元する対象は次の二段階です。

1. **ウィンドウ配置**: アプリ、位置、サイズ、モニター、最小化・最大化など。
2. **アプリ内状態**: MCP サーバーを提供するアプリに限り、アプリが公開する復元情報を利用して復元する。

レイアウトには名前を付けて保存でき、ローカル REST API 経由で呼び出せます。主な利用例は Stream Deck のボタンからのレイアウト切替です。

## 2. 決定事項

| 項目 | 決定 |
| --- | --- |
| 製品名 | **Kankei** |
| 漢字表記 | **還景** |
| 対象 OS | Windows |
| 外部操作 | ローカル REST API |
| アプリ内状態の復元 | MCP 対応アプリのみを初期対象にする |
| 可視化 | 復元中、完了、失敗をメインモニター中央のオーバーレイに表示する |
| 基本姿勢 | 失敗したアプリがあっても、残りの復元処理は継続する |

## 3. MVP の範囲

### 含める

- 実行中ウィンドウのスナップショットを保存する。
- 保存済みレイアウトを呼び出し、対象アプリを起動または前面化し、ウィンドウ位置・サイズを復元する。
- MCP 対応アプリに状態のエクスポート／インポートを依頼するためのアダプター基盤を用意する。
- `POST /v1/layouts/{layoutId}/restore` で復元を開始できるローカル REST API を提供する。
- 復元進捗を中央オーバーレイと REST API のジョブ状態で確認できる。

### MVP では含めない

- MCP 非対応アプリの文書・タブ・ログイン状態などの内部状態の推測復元。
- クラウド同期、複数 PC 間同期。
- 外部ネットワークへ公開する REST API。
- OS の終了／再起動そのものを Kankei が実行する機能。

## 4. 利用フロー

1. ユーザーが「保存」を実行する、または終了前の自動保存を有効にする。
2. Kankei がウィンドウ一覧と配置を保存する。
3. MCP 対応アプリには、任意で状態スナップショットのエクスポートを依頼する。
4. ユーザーまたは Stream Deck が REST API でレイアウト復元を要求する。
5. Kankei が復元ジョブを作成し、中央オーバーレイを出す。
6. 各アプリを順番に起動・配置・状態復元し、結果を表示する。

## 5. 復元オーバーレイ案

メインモニター中央に、短時間だけ表示する半透明の常に手前のウィンドウ。

```text
還景  ── 「開発」レイアウトを復元中

⏳ Visual Studio             復元中
☑ Windows Terminal           復元完了
☑ Microsoft Edge             復元完了
×  Foo App                   復元できませんでした

4 / 5 完了
```

- 完了後は数秒で自動的に閉じる。
- 失敗がある場合は、失敗理由を詳細ビューまたは通知履歴で確認できるようにする。
- 成功・失敗・スキップを明確に分ける。失敗アプリがあってもジョブ全体を中断しない。

## 6. REST API の初期案

REST API は**必ず localhost にだけバインド**し、初期値は `127.0.0.1:48120` とする。将来、API トークンまたは OS ユーザー限定の認可を追加する。

| メソッド | パス | 用途 |
| --- | --- | --- |
| `GET` | `/v1/health` | 起動確認 |
| `GET` | `/v1/layouts` | レイアウト一覧 |
| `POST` | `/v1/layouts` | 現在の配置を名前付きで保存 |
| `POST` | `/v1/layouts/{layoutId}/restore` | 非同期の復元開始 |
| `GET` | `/v1/restores/{restoreId}` | 復元ジョブ状態 |
| `GET` | `/v1/restores/{restoreId}/events` | 進捗イベント（SSE は後回しでもよい） |

復元開始の例:

```http
POST /v1/layouts/development/restore
Content-Type: application/json

{
  "showOverlay": true
}
```

応答例:

```json
{
  "restoreId": "rst_01J...",
  "status": "running"
}
```

Stream Deck 側は HTTP リクエストを送るだけでよい。実装初期は Stream Deck 専用プラグインを作らない。

## 7. MCP 連携の境界

Kankei は特定アプリの内部状態を理解しない。各アプリ用アダプターが、MCP を通じて以下を行う。

```text
Kankei
  └─ Application restore adapter
       ├─ exportState()     : 保存時に復元データを取得
       ├─ launchOrFocus()   : 必要ならアプリを起動
       ├─ importState(data) : 復元時に状態を渡す
       └─ describeFailure() : ユーザー向け失敗理由を整形
```

アダプターの初期契約案:

```text
App identity: executable path / package family / MCP server identity
Snapshot:    versioned JSON
Restore:     idempotent を目標とする
Timeout:     アプリごとに設定可能。タイムアウトは失敗として次へ進む
```

MCP 非対応アプリは「配置だけ復元」の対象とし、アプリ内状態の復元を試みない。

## 8. 技術設計のたたき台

Windows ネイティブ機能とローカル HTTP を扱いやすい .NET を第一候補とする。

```text
Kankei Desktop（通知領域常駐・設定画面・オーバーレイ）
  ├─ Window Discovery       Win32 / UI Automation
  ├─ Layout Store           SQLite または JSON（初期は JSON でも可）
  ├─ Restore Orchestrator   順序・リトライ・タイムアウト・結果集計
  ├─ MCP Adapter Host       アプリごとの状態保存／復元
  └─ Local API Host         ASP.NET Core Minimal API
```

### 保存するウィンドウ情報の候補

- アプリ識別子: 実行ファイルパス、AppUserModelID、パッケージ情報。
- ウィンドウ識別ヒント: クラス名、タイトル（秘密情報になり得るため保存方針に注意）。
- 配置: モニター識別子、DPI、矩形、表示状態、Z オーダーのヒント。
- 起動情報: コマンドラインは扱いに注意し、既定では保存しない。
- アプリ内状態: MCP アダプターが返すバージョン付き JSON。

## 9. 重要なリスクと設計上の注意

- **復元の完全性**: Windows は任意アプリの内部状態を一般に復元できない。MCP 対応アプリに限定する方針が必要。
- **識別の不安定性**: 同一アプリの複数ウィンドウをタイトルだけで対応付けると誤復元する。アプリ側で安定したウィンドウ ID を返せるとよい。
- **マルチモニター**: モニターの抜き差し、解像度、DPI 変更時の座標変換と画面外補正が必要。
- **特権境界**: 管理者権限で動くウィンドウは通常権限の Kankei から操作できない可能性がある。
- **REST API の安全性**: 外部公開しない。localhost 限定、CSRF を受けにくい設計、将来的なトークン認証を検討する。
- **プライバシー**: ウィンドウタイトルや MCP スナップショットには機密情報が含まれ得る。保存先の暗号化や、アプリごとの除外設定を早期に用意する。

## 10. 次に決めること

1. デスクトップ UI 技術: WPF、WinUI 3、Avalonia のどれにするか。
2. 初回対応アプリ: まず一つ、実際に MCP 状態復元まで通せる対象を決める。
3. レイアウト保存の契機: 手動保存のみで始めるか、終了通知を使った自動保存も MVP に入れるか。
4. REST API の認証方針と Stream Deck からの呼び出し方法。
5. 配置復元の成功条件と、失敗・スキップの表示文言。

## 11. 最初の実装マイルストーン

1. 常駐アプリから現在のトップレベルウィンドウを列挙し、JSON に保存する。
2. 保存済みウィンドウを前面化し、位置とサイズだけを復元する。
3. 中央オーバーレイにアイテム別の進捗と成功・失敗を表示する。
4. localhost REST API から同じ復元ジョブを起動する。
5. MCP 対応アプリ一つに対して、アプリ内状態の保存・復元を通す。
